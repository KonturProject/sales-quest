# The admin's journal and the cancel of a correction — Implementation Plan (2b-3, release 2)

> **For agentic workers:** executed inline in the authoring session (executing-plans with a ledger and TDD); an
> independent review subagent (opus) checks the whole plan at the end (Task 6). Steps use checkbox (`- [ ]`)
> syntax. Before each task: its «Где смотреть» block and `docs/NAVIGATOR.md` §3.

**Goal:** «Журнал» in the admin — every action of the game since its launch, from the repository's history, with a
filter; an import opened shows its per-operator «было → стало» from the data as they were; a correction can be
cancelled from there (one commit «отмена корректировок: N»); the journal flags past corrections the exports have
brought since (a double count).

**Architecture:** the GitHub client gains `history` (the commits of `data/` on `main`) and the pipeline reads a
season at any commit. A pure `src/admin/journal.ts` turns commits into entries by their public lines, tells what one
commit changed (`entryDetails`), finds past double counts (`pastDoubles`) and prepares a batch of cancels
(`prepareCancels` → a `BatchView`). A screen `Journal.tsx` loads the list, the details and the states it needs on
demand (cached for the visit), and writes cancels through the existing `BatchDraft`. The per-operator table moves
to `ChangesTable.tsx`, shared with the import preview.

**Tech Stack:** React 19, TypeScript 6 strict, Vitest, Playwright 1.63 (GitHub faked in the browser).

**Spec:** `docs/superpowers/specs/2026-10-19-journal-undo-design.md` (approved 19.10.2026) — release 2 of three;
D-61 (release 1), D-53, D-51, SPEC ADM-LOG, ADM-UNDO, SEC-5.

## Global Constraints

- The token goes to `https://api.github.com` only; the list is built from public commit lines, decryption only for
  details and for the double-count check.
- Only the current season (`data(<seasonId>):`), back to and including its launch («новая игра …»).
- The public line of the cancel: `отмена корректировок: N` — counts only (`commitChange` refuses a name).
- A cancel always has the author's reason; nothing is cancelled without «Записать» (the `BatchDraft` way).
- «Now» is a parameter in pure code (D-11); timestamps by `localTimestamp`.
- Russian UI text, English comments; `sq-*` classes (D-46); the admin stays a lazy chunk (D-7a).
- No real names in code, tests, docs or commits.

## Review Focus

1. **A history read failing midway** (network, rate limit, a commit whose files cannot be decrypted): the journal
   shows what it has and a plain message, never the admin's error page; the cancel batch still works.
2. **A correction cancelled meanwhile in another tab** while it sits in the journal's batch: the `BatchDraft`
   conflict path re-reads and the line turns into a named problem.
3. **Commits outside the game** (the demo, development commits touching `data/`, an earlier season): never listed,
   never opened.
4. **A correction offset by a «−1»**, or one whose commit cannot be found: no false «похоже на двойной счёт».
5. **The journal opened on a closed game** (after «Подвести итоги» on 26.10): it lists and cancels as before (D-59:
   corrections after the closing are allowed).

### Task 2: The journal, pure — entries, details, past double counts, a batch of cancels

**Где смотреть:** `src/admin/importDiff.ts` (`importChanges`, `manualOf`, `doubleCounts`), `src/admin/corrections.ts`
(`revokeAdjustments`), `src/admin/BatchDraft.tsx` (`BatchView`), `src/admin/pipeline.ts` (`previewChange`),
`src/finale/results.ts` (`manualCount`), real public lines: `git log --format=%s -- data/`.

**Files:** Create `src/admin/journal.ts`, `tests/unit/admin/journal.test.ts`.

**Interfaces:**
- Consumes: `CommitInfo` (Task 1), `importChanges`, `OperatorChange`, `revokeAdjustments`, `previewChange`.
- Produces:

```ts
export type JournalKind = 'import' | 'corrections' | 'cancels' | 'roster' | 'finale' | 'launch' | 'other';
export type JournalEntry = { sha: string; parent: string | null; at: string; kind: JournalKind; line: string; by: string };
/** The season's entries, newest first, down to and including its launch; other seasons' and non-data commits out. */
export function journalOf(commits: CommitInfo[], seasonId: string): JournalEntry[];
export function kindOf(line: string): JournalKind;
// 'импорт: …' import · 'корректировки: …' corrections · 'отмена корректировок: …' cancels · 'состав: …' roster ·
// 'итоги игры …', 'игра снова идёт: …' finale · 'новая игра …' launch · anything else other

export type EntryDetails = {
  imports: ImportLog[]; // added by the commit
  changes: OperatorChange[]; // importChanges over the added imports' days (min from … max to); [] without imports
  added: Adjustment[]; // added by the commit
  revoked: Adjustment[]; // cancelled by the commit (revoked in `after`, not in `before`)
};
export function entryDetails(before: EngineInput, after: EngineInput): EntryDetails;

export type PastDouble = {
  managerId: string; date: string; metricId: string;
  manual: number; // the net manual count now
  then: number; // the records when the earliest of its positive corrections was written
  now: number; // the records now
  adjustmentIds: string[]; // the active positive corrections of the key
};
/**
 * Keys with a net manual count > 0 now whose records grew since the earliest positive correction was written —
 * `thenOf(id)` the season at that correction's commit (undefined: not found → no flag).
 */
export function pastDoubles(now: EngineInput, thenOf: (adjustmentId: string) => EngineInput | undefined): PastDouble[];
/** The commit a correction was written in: the oldest import or corrections entry at or after its `at`. */
export function commitOf(entries: JournalEntry[], adjustment: Adjustment): JournalEntry | undefined;

export type Cancel = { id: string; reason: string };
/** Cancels as a `BatchDraft` batch: one line each, problems by index, message «отмена корректировок: N». */
export function prepareCancels(state: RepoState, cancels: Cancel[], opts: { by: string; now: string }): BatchView;
```

`manualOf` moves from `importDiff.ts` to an export there (`manualCounts(adjustments, config)`), used by both.
A cancel's line: `Отменить «<reason>» — <operator>, ДД.ММ: <причина отмены>` (screen only); an empty reason is a
problem «укажите причину отмены»; an id gone / already cancelled — the `revokeAdjustments` messages.

### Task 4: The screen «Журнал» and the cancel from it

**Где смотреть:** `src/admin/Home.tsx`, `src/admin/AdminPage.tsx` (views, `committed`), `src/admin/BatchDraft.tsx`,

**Files:** Create `src/admin/Journal.tsx`; Modify `src/admin/Home.tsx`, `src/admin/AdminPage.tsx`; Test
`tests/e2e/admin.spec.ts`.

**Interfaces:**
- Consumes: `history`, `loadRepoState(…, at)` (Task 1); `journalOf`, `entryDetails`, `pastDoubles`, `commitOf`,
  `prepareCancels` (Task 2); `ChangesTable` (Task 3).
- Produces: `Home` prop `onJournal`; View `'journal'`; `Journal({ session, onState, onCancel, onCommitted })`.

The screen: «Журнал» title; «Читаю историю…» while loading; a filter row of buttons with `aria-pressed` — «Все»,
«Загрузки», «Корректировки», «Отмены», «Состав», «Итоги» (finale + launch); entries as a list (`aria-label="Журнал"`):
local «ДД.ММ ЧЧ:ММ», the kind's word, the public line, who; «Подробнее» opens the details (read and decrypted then:
the commit and its parent, cached by sha for the visit) — an import: its file, days and `ChangesTable` (no actions);
added corrections, each with its operator, day, reason and its state now: active → «Отменить», cancelled → struck
through «отменена ДД.ММ: <причина>»; cancelled ones of the commit listed as such. A panel «Похоже на двойной счёт»
(`aria-label`) above the list once the check is done («Проверяю прошлые корректировки…» before): each flagged key —
operator, day, metric, «было N → стало M», the correction's reason, «Отменить». «Отменить» opens a field «Причина
отмены» and «В отмены»; the cancels go to a `BatchDraft` (name `cancels`, title «Отмены») at the top of the screen. A
failure of the list or of a detail is a message in place (`role="alert"`), the rest of the screen stays.
