Запуск настоящей игры (D-51): профили двух выгрузок, импорт в воркере с превью и одним коммитом, мастер
«Новая игра», QA-2 и QA-3. Из прежнего списка закрыты: ~~состав из воронки — только активные~~ (мастер отмечает

- **Перевод человека в другую группу в мастере** не предусмотрен: группа берётся из воронки (D-21). Переводы —
  в форме состава (2б, ADM-ROSTER).
- **Мастер разметки выгрузок** (общий, из ТЗ §9) — когда формат выгрузки поменяется (OQ-13).

Из независимого ревью 2а (мелкое, отложено; важное исправлено — D-51):
- **Нули оплат** ставятся только операторам групп, которые есть в файле (OQ-12): если у команды в новой
  выгрузке нет ни одной оплаты, её отменённая оплата за период останется. Выгрузка оплат — на весь отдел,
  можно ставить нули всем командам с `sourceCode`.
- ~~Ошибки GitHub точнее~~ — сделано в 2б-1 (D-52).
- **Права fine-grained ключа:** `permissions.push` из `GET /repos` может отражать роль владельца, а не права
  ключа — ключ только на чтение пройдёт вход и получит понятную ошибку 403 на первой записи. Проверить при
  запуске.
- **Подсказка на входе до запуска:** пока на сайте демо, фраза — `sales-quest-demo` (она публична, D-32);
  экран входа может это сказать.
- ~~Тексты ошибок~~ (экран настроек, плашка ошибки, «Назад» во время записи, `TypeError`) — сделано в 2б-1.
- **Тёзки:** два разных человека с одинаковым ФИО сольются в одного оператора; мастер их отвергнет
  («в списке дважды»). Предупреждать при импорте, если одно имя встречается в двух группах.
- **Исправить запуск:** опечатку в имени руководителя, нормативы или даты до конца игры не поправить
  (мастер не запускается поверх идущей игры) — форма команды в 2б или перезапуск, пока в игре нет загрузок.
- **Перед новой игрой после прошлой** предупредить, что в прошлую больше нельзя будет загрузить поздние
  данные (типично — оплаты пятницы, загруженные в понедельник).

### Сделано в плане 2б-1 (11.10.2026)

Экран «Состав и команды»: новички, переводы, увольнения и возвраты, ФИО и нормативы, руководитель, цвет, герой
и порядок команд — одной пачкой с превью и одной записью (D-52).

Из независимого ревью 2б-1 (мелкое, отложено; важное исправлено):
- **Округление нормативов в форме:** норматив 0,1667 показывается как «0,167» и при любой правке оператора
  записывается округлённым (сейчас у всех 3 / 1,5 / 0,2 — не задевает).
- **Переводы:** перевод в команду, куда человек и так переходит с того же дня, проходит как «1 перевод»; отмена
  запланированного перевода более ранней датой отвергается «уже в этой команде»; отброшенные позже даты членства
  (например, перевод другого админа с 20.10) не показываются в превью; при отказе «перевод после увольнения»
  подсказать «сначала «Вернуть»».
- **Тексты:** предупреждение о нулевых нормативах нового человека пишет «у оператора»; два изменения цвета одной
  команды дают одно предупреждение дважды; правки отклонённого «Новый» читаются «оператор new-1»; форма
  увольнения говорит «в этот день ещё в команде», а экран в этот день уже числит его в «Уволенных»; «Операторы (N)»
  считает ещё не пришедших, «N чел.» — нет; не сказано, что нормативы действуют на всю игру, а «Вернуть» снимает
  увольнение целиком (это не повторный приём).
- **Форма оператора** сравнивает ФИО через `trim`, а не `cleanName`: двойной пробел даёт красное «ФИО не
  изменилось»; `parseDecimal` принимает «0x10» и «1e3».
- **GitHub:** вторичный лимит (403 при оставшихся запросах) и 429 читаются как «нет прав» или общая ошибка.
- **Повторный приём после перерыва** (уволен, вернулся позже в другую команду) — отдельной правки нет.

### Сделано в 2б-2 (корректировки, D-53)

Шаги команде ±N без долга, показатели оператора за день баллами, команда на старт — экран «Корректировки»
пачкой (`docs/superpowers/plans/2026-10-11-stage-2b2-corrections.md`).

Из независимого ревью 2б-2 (мелкое, отложено; критичное и важное исправлено):
- **Время записи корректировок** берётся с последней перерисовки экрана «Корректировки», а не с нажатия
  «Записать»: пачка, оставленная на ночь, запишется вчерашним вечером (и задним числом попадёт в повтор дня).
- **Предупреждение «меньше нуля»** при дробных весах может сработать на «−0» (сравнение без допуска); сейчас
  веса целые.
- **«На старт»** для команды, которая уже на старте (или второй раз в одной пачке), записывается пустым
  действием, а не отклоняется.
- **Длинное тире** «—3» в поле шагов не читается как минус (отказ, а не ошибка в числе).
- e2e «данные изменились» для корректировок: коммит «другого админа» не меняет данных — пересчёт пачки на
  свежих данных проверяет только unit-тест.

Из независимого ревью отпуска (D-54; мелкое, отложено; важное исправлено):
- **Счёт «(N раб. дн.)»** в строке пачки и предупреждение «нет рабочих дней» считают дни игры, а не дни
  человека: отпуск новичка до его прихода или с увольнением внутри показывает лишние дни; увольнение раньше
  записанного отпуска принимается молча (отпуск остаётся в данных без действия).
- **Вся команда в отпуске всю игру:** цель 0, фигурка стоит без предупреждения (предупреждение движка требует
  численность > 0).
- Комментарий `teamAllMembers.ts` без «или в отпуске»; тип `Vacation` экспортирован, но не используется.

### Сделано: моменты на панелях и «Что нового» (D-56)

Карточки считают баллы порции, «до шага», тосты «кто принёс баллы», баннеры ачивок, «Герои дня», проигрывание

- **Карточки при ширине 1024 px** (шесть колонок с `lg`) тесные и до этой работы: «клетка … из …» и темп
  переносятся; «+N» у имени на 4 с обрезает длинные имена.
- **Скриншот-тест «rest»** однажды упал в общем прогоне: модели на снимке ещё без текстур (гонка загрузки сцены
  под параллельной нагрузкой); отдельно и при повторе — зелёный.
- Ачивка, полученная на дневных цифрах, может исчезнуть после утренней воронки — баннер о ней уже был показан.

### Сделано: «Промежуточные итоги» (D-55)

Дневная выгрузка без дат — группы и их операторы, B — `inv6`, C — `inv20`, за выбранный день
(`docs/superpowers/plans/2026-10-13-intraday-import.md`).

Из независимого ревью D-55 (мелкое, отложено; важное — узнавание файла, где у первых операторов групп пустые
ячейки, — исправлено):
- **Строка итога** («Общий итог», «Итого») без кода группы читалась бы как оператор последней группы с числами
  всего отдела; в образце автора такой строки нет (проверено по устройству файла). Если появится — пропускать.
- **Мастер «Новая игра»** пишет в конфиг следующей игры все три профиля: вкладка со старым кодом, не обновлённая
  с прошлого деплоя (ТВ-экран), не прочтёт такой конфиг. Можно писать только воронку и оплаты — `profilesFor`
  добавит остальное из кода.
- **Поле «День» не заблокировано во время «Записываю…»** (как и поля периода оплат): смена дня в этот момент и
  конфликт записи дают превью старого дня при новом значении поля.
- **Будущий день игры** принимается: `max` поля — конец игры, а не сегодня; e2e проверяет только очищенный день,
  не день вне игры.
- IMPORT_FORMATS §5 «ФИО в обоих файлах» — теперь в трёх; `chooseDay` (как `choosePeriod`) не сбрасывает
  прежнюю ошибку.
- **«Последние загрузки»** на главной админки — 6 последних: несколько дневных загрузок вытесняют из списка
  воронку и оплаты (журнал импортов хранит всё).

## Когда-нибудь

- Закрепить GitHub Actions по SHA коммита, а не по тегу.
- Игра, начатая в субботу: данные за первые выходные идут в баллы команды, но не попадают ни в одну
  неделю (неделя без рабочих дней отброшена). Рекомендуем начинать с понедельника (OQ-19).
- Почта автора коммитов видна в публичной истории: для будущих коммитов можно перейти на
  адрес `…@users.noreply.github.com` (решает автор).
