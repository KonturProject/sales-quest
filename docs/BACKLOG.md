# Отложенные задачи

Замечания и идеи, которые относятся к будущим этапам. При планировании этапа — пройтись по его разделу
и перенести пункты в план (или закрыть с причиной).

## Этап 1 — движок и данные

- **Проверка правил хука в CI** (ревью этапа 0). Хук не видит коммиты через GitHub API (админка
  этапа 2), `--no-verify` и клоны без `npm install`. Когда появится `data/`: в CI прогонять те же
  правила (`findViolations`) по диапазону пуша `before..sha`.
- **Проверять `*.enc.json` по содержимому, а не по имени** (ревью этапа 0): файл обязан быть
  конвертом `{v, alg, salt, iv, ciphertext}`; открытый JSON с именем `*.enc.json` сейчас прошёл бы.
- **Копирование `data/` в сборку** (DEP-2) — в Vite-сборке, чтобы локально и в CI было одинаково.

### План 1б — ачивки (из ревью плана 1а)

- **Скорость таймлайна.** Замер на 70 операторах, 22 рабочих днях, половине с нормативами и
  44 корректировках (прогретый режим): `prepare` 0,8 мс, `computeGameState` 3,5 мс, `buildTimeline`
  9,9 мс — около 14 мс вместе; первый (холодный) прогон до ~33 мс. На i3 4-го поколения может быть
  в 3–4 раза дольше. Таймлайн для каждого дня заново считает цели и численность команд, хотя от дня
  они не зависят: считать их один раз на игру. Мерить вместе с ачивками, бюджет ARCH-2 — 50 мс.
- **`computeGameState(prepared, today)`** — вариант без повторного `prepare`, когда ачивки и
  таймлайн уже подготовили данные.
- **Порядок при `achievementBonusAffectsSteps`:** ачивки операторов → бонусные баллы → позиции
  команд. Иначе бонус и позиции ссылаются друг на друга.
- **«Первым вошёл в локацию» в один день:** таймлайн дневной; нужно правило ничьей (обе команды
  получают, или по баллам, или по времени импорта).
- **Ранг прошлых недель и увольнения (R-5).** Лидерборд скрывает уволенного на всё время с даты
  увольнения — для текущего рейтинга это верно. Но «лидер недели» за неделю, когда человек ещё
  работал, должен считаться по составу той недели: для ачивок `rank` проверять участие на конец
  периода, а не на «сегодня».
- **`team_pace`** зависит от решения OQ-21 (общий темп или темп команды).

## Этап 2 — админка

- **«Долг» отрицательных шагов.** Команда на 5-й клетке, админ даёт −10 (показ 0), потом +3 — фигурка
  всё ещё на 0: шаги копятся ниже нуля. Так написано в FR-STEP-3; превью админки должно это показывать
  или обрезать сохраняемое значение.
- **Корректировка баллов** в форме админки — с полем «за какой день» (D-25).
- **Метки времени** админка пишет одним помощником в местном времени с поясом (`+03:00`, D-11) —
  сделать его в плане 1в вместе с остальным слоем данных.

## Этап 3 — сцена

- **Выбор подхода к локациям** (D-23): «расписная доска» (ИИ-арт автора из `refs/` как текстура
  плоскости + 3D-персонажи и немного объёмных объектов) против сборки из CC0-наборов моделей.
  Учесть бюджет текстур (≤ 64 МБ в GPU, §12.1): 4 картинки 2048² без сжатия — ~85 МБ с мипмапами,
  значит 1024² или сжатые текстуры (KTX2/Basis).
- **Число клеток на локацию** (OQ-18): прогнать демо-месяц этапа 1 при 10 и 20 клетках, показать автору.

Сцена этапа 0 — заглушка; при переходе на перспективную камеру с пролётами (D-23):

- `MapScene`: проп `angles` читается только при монтировании — R3F 9 не пересоздаёт камеру,
  заданную объектом настроек, а плитки при этом повернутся. Камеру этапа 3 держать в своём
  компоненте-риге (ref на камеру, пересчёт при смене `ui.camera` и размера окна). `zoom` сейчас
  тоже фиксируется по ширине окна при монтировании; `lookAtOrigin` дублирует поведение R3F.
- `FrameCounter` считает тики цикла R3F, а не реальные отрисовки WebGL: при своём 30-FPS тикере
  (PERF-1) дополнительно отдавать `gl.info.render.frame`.
- `App` размонтирует канвас на любом другом маршруте. Лидерборд (`#/leaderboard`) должен
  накрывать сцену и замораживать её (PERF-6), а не пересоздавать WebGL-контекст и ассеты.
- `npm run size` считает начальный JS по `modulepreload`-ссылкам; при `build.modulePreload: false`
  он бы недосчитал. Надёжнее — `build.manifest: true` и обход статических `imports` точки входа.
- **Численность в таблице команд (FR-LB-3):** `TeamState.headcount` — средняя за всю игру (с будущими
  новичками); для показа нужна текущая — число неуволенных в команде на сегодня.

## Когда-нибудь

- Закрепить GitHub Actions по SHA коммита, а не по тегу.
- Игра, начатая в субботу: данные за первые выходные идут в баллы команды, но не попадают ни в одну
  неделю (неделя без рабочих дней отброшена). Рекомендуем начинать с понедельника (OQ-19).
- Файлы данных (план 1в): схемы файлов целиком со `schemaVersion` (DATA-15) и проверкой
  уникальности `id` корректировок.
- Почта автора коммитов видна в публичной истории: для будущих коммитов можно перейти на
  адрес `…@users.noreply.github.com` (решает автор).
